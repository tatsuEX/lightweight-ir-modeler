# Global Toast（PrimeFaces Growl 相当）

Date: 2026-08-28 07:11

## Problem / goal

アプリ各所（Import / Export / snapshot 保存失敗など）から、画面固有の Alert に頼らず **同じ Toast 面** へメッセージを出せるようにする。  
イメージは [PrimeFaces Growl](https://showcase.primefaces.org/ui/message/growl.xhtml): `FacesContext.addMessage` → `<p:growl>` が表示 → `life` 後に消える（`sticky` なら手動閉じるまで残る）。

## Proposed approach

JSF の対応関係を次のように置く。イベントバスは使わない（初期スコープ外）。

| PrimeFaces / JSF | 本アプリ |
|---|---|
| `FacesMessage`（severity / summary / detail） | `ToastMessage` |
| `FacesContext.addMessage` | `ToastMessages.add` / `info` / `warn` / `error` |
| `<p:growl>`（1 ホスト） | ルート `+layout.svelte` の `GlobalToast` |
| `life`（既定 6s。Flowbite デモは 5s） | store 定数 `DEFAULT_TOAST_DELAY_MS`（推奨 5000） |
| `sticky` | メッセージ単位の `sticky?: boolean` |
| `for` / 複数 growl | **MVP ではやらない**（キューは 1 本） |

表示は **flowbite-svelte の `Toast` + `ToastContainer`**（追加 npm なし）。  
`color`: info → `green`、warn → `yellow`、error → `red`（Growl の Info/Warn/Error に寄せる）。

### 責務分割

1. **Store（FacesMessage 相当）** — `src/lib/store/toast/toast.svelte.ts`  
   - `#messages = $state<ToastMessage[]>`  
   - `add` 時に id を採番し配列へ追加。`sticky` でなければ `setTimeout` → `dismiss(id)`  
   - timer id は **非公開 `Map`**（呼び出し側に漏らさない）  
   - `dismiss` は timer を `clearTimeout` してから配列から除去  
2. **Host（growl 相当）** — `src/lib/components/GlobalToast.svelte`  
   - `getToastContext()` し `{#each messages}` で Toast を描画  
   - 閉じるボタンは `dismiss(id)`  
   - **追加検知用の `$effect` は置かない**。配列の `$state` 更新がそのまま描画になる。timer を Host の `$effect` に置くと二重発火・リークしやすい。
3. **配線** — `src/routes/+layout.svelte` で `setToastContext` + `<GlobalToast />`  
   - layout-editor 配下に閉じない（「アプリケーションの各所」）。

呼び出し例（呼び出し側は id / timer を知らない）:

```ts
const toast = getToastContext();
toast.info('保存しました', 'snapshot を更新しました');
toast.warn('未保存の変更があります');
toast.error('Export に失敗しました', error.message);
toast.add({ severity: 'info', summary: '…', detail: '…', sticky: true });
```

### データモデル（MVP）

```ts
type ToastSeverity = 'info' | 'warn' | 'error';

type ToastMessage = {
  id: string;
  severity: ToastSeverity;
  summary: string;
  detail?: string;
  sticky: boolean;
};
```

`fatal`・`for` キー・`application.yml` の delay 設定は後回し（YAGNI）。

### 補足: ユーザー認識との差分

「messages 追加を検知して Toast 表示、delay 後に state から削除」は正しい。  
実装上の検知は **Host の `{#each}`（Svelte の反応）** で足り、別レイヤの observer は不要。  
delay 後の削除は **store の `add` が timer を持つ** 方が、Host の mount 寿命と切り離せて小さい。

## Alternatives considered

| 案 | 採用しない理由 |
|---|---|
| layout-editor Context のみ | TOP など他ルートから使えない |
| module singleton | Context API ルール（store-presentation）に反する |
| Host `$effect` で timer | 二重スケジュールしやすい。store の `add` の方が小さい |
| PrimeFaces `for` / 複数ホスト | 今の画面に複数キューの需要がない |
| Import モーダル内 Alert を即 Toast 化 | モーダル内エラーはフォーム近傍の方が分かりやすい。後続で任意 |

## Key decisions / open questions

推奨（確認待ち）:

1. 第 1 スライスは **基盤のみ**（store + Host + ルート配線 + store 単体テスト）。既存画面への差し込みは次スライス。
2. **sticky は MVP に含める**（フラグ 1 本で Growl の Sticky 相当）。
3. delay は **コード定数**。`application.yml` は触らない。
4. outro アニメ用の二段階 dismiss（`visible: false` → 300ms 後に除去）は任意。最初は即 `filter` でよい。

未決:

- 第 1 スライスで動作確認用の一時ボタンを置くか（ルート TOP は本番に残したくない。実装時はブラウザで `toast.info` を 1 箇所から叩く）。
