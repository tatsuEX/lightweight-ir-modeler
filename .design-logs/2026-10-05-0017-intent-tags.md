# User Intent Tags

Date: 2026-10-05 00:17

## Problem

Java のアノテーション、TS のデコレータ、Rust の derive のように、UI コンポーネントへ「何をしたいか」を宣言し、writer pipeline が target ごとに解釈できる仕組みが欲しい。Property 画面はすでに情報密度が高いので、列を増やさずに付与・確認できる UI が必要。

## Naming

**Intent Tags（意図タグ）** を採用する。宣言だけを持ち、解釈は target に委ねる（無視してもよい）性質が名前に出る。

- Export Hints: snapshot や将来の meta で意味が弱い
- Directives: 強制に聞こえ、target が無視できることと矛盾する
- Annotations: 運用コメント（YAML コメント）と混同しやすい
- Traits / Derives: 振る舞い付与のニュアンスが強すぎる

## Approach

### IR

- `components[].intentTags?: string[]` を追加する（追加的なので migration なし）。空になったらキーを消す
- タグ id の文法は `<name>[:<arg>]`（`auto-layout`、`validator:email`、`depends-on:user-name`）
- `UIDefinition.addIntentTags(ids, tags)` / `removeIntentTags(ids, tags)`
- meta への横展開は型を足さず、ダイアログを対象非依存にして後から載せる

### マスタ

`application.yml` の `ir.intentTags` に IR 種類ごとのファイル一覧を書き、一覧順に合成する。

```yaml
ir:
  intentTags:
    - irType: ui-definition
      files:
        - path: ./config/intent-tags-default.yaml
          alias: default
        - path: ./config/intent-tags-common.yaml
          alias: common
    - irType: layout
      files:
        - path: ./config/intent-tags-validators.yaml
          alias: validators
```

- マスタファイルは `tags: [{ id, description }]` だけを持つ。IR 種類は設定側だけが決めるので、同じファイルを複数の IR 種類に割り当てられる
- 同じ irType 内で id が重複したら先勝ち + warn ログ。存在しないファイルは空として扱う
- GUI からの新規登録先は、その irType の alias `default`。無ければ登録は 503
- `default` のファイルがほかの irType からも参照されていれば、登録前に opt-out 可能な警告を出す（「Intent TagsマスタがほかのIR種別 (Layout, ...) からも参照されています」）。opt-out は localStorage、キーは登録元 irType と共有先 irType の組
- 設定キーは `irType`。Export の adapter-target（`target`）と語彙を分ける

### UI

- Property の「#」列に、タグがある行だけ Tag アイコンと件数を出す。クリックで閲覧ダイアログ（header `components[logicalId]`）
- ヘッダの「Intent Tags」ボタンで編集ダイアログ。付与状況チップ、候補付き TagsInput、新規タグの説明欄、「選択に反映 / 選択から削除 / すべてに反映 / すべてから削除」

### Export

- `ir-to-raw-fields` で `intentTags` を Raw のフィールドへ載せる。target ごとの解釈 step は次段

## Alternatives considered

- マスタ 1 ファイル（`ir.intentTags.file`）: プロジェクト間共有ができないため不採用
- マスタファイル側に `target-ir-type` を持つ: 同じファイルを複数 IR 種類で使えないため不採用
- 設定キー `target`: adapter-target と紛らわしいため `irType` にした

## Open questions

- 再 Import でタグが失われる（components を置き換えるため）。現状は docs の WARN に留める
- target ごとの解釈 step（im-forma の `auto-layout`、primefaces の `validator:email` など）の仕様
